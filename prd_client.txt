1. Project Overview
TripDash adalah sebuah web dashboard (SaaS) yang membaca dan memproses data dari Google Spreadsheet (hasil input Google Form pelanggan) untuk mengotomatisasi proses verifikasi pembayaran, pembuatan dokumen PDF absensi, pelacakan arus kas (keuangan), serta manajemen inventaris barang UMKM Open Trip.
2. Problem Statement
2.1 Background
Dalam operasional bisnis open trip skala UMKM, sering kali hanya terdapat 1 (satu) orang admin yang harus merangkap berbagai peran. Admin ini bertanggung jawab atas pembuatan form pendaftaran, desain poster, promosi media sosial, customer service, hingga tugas manajerial seperti merekap peserta, mengecek mutasi transfer, mengecek status grup WhatsApp, membuat lembar absensi, merekap keuangan, dan mendata barang inventaris/sewaan.
2.2 Current Situation
Seluruh proses manajerial tersebut saat ini masih dilakukan secara manual. Proses ini sangat memakan waktu, menguras energi admin, dan memiliki risiko human error yang tinggi (seperti salah hitung tagihan atau peserta terlewat dari absensi).
2.3 Expectation
Perlu adanya sistem yang mengotomatisasi sebagian alur kerja (workflow) admin, khususnya pada tahap pasca-pendaftaran, sehingga mempermudah, mempercepat, dan meningkatkan akurasi admin dalam mengelola operasional trip.
3. Target Users
Administrator Operasional (Single Role): Aplikasi ini hanya memiliki satu jenis role pengguna (Admin) yang diwajibkan untuk login ke dalam sistem. Pengguna ini adalah representasi dari pengurus trip yang merangkap berbagai tugas sekaligus (keuangan, customer service, dan manajemen inventaris).
4. Scope of Work (MVP)

In-Scope Requirements
Out-of-Scope Requirements
Sistem Autentikasi Dasar: Fitur Login khusus untuk satu role Admin.
Integrasi Data & Pemetaan: Penarikan data dari link Google Spreadsheet via API ke dalam tabel interaktif di dashboard.
Verifikasi Pembayaran Pintar: Kalkulasi tagihan dinamis (berdasarkan jenis transport & add-ons), validasi manual/otomatis, serta deteksi rombongan dengan 1 bukti transfer.
Generator PDF Absensi: Ekspor data peserta (semua status lunas/belum) menjadi PDF, termasuk pemisahan nama gabungan dalam satu baris.
Finance Tracker Terpadu: Pencatatan otomatis uang masuk (via timestamp), penambahan pengeluaran kustom, dan filter laporan (trip, bulan, tahun).
Manajemen Inventaris Dasar: Pencatatan dan pengelolaan ketersediaan barang operasional dan barang sewaan trip.
B2C Landing Page: Pembuatan halaman pendaftaran user dari nol (Pelanggan tetap mendaftar via Google Form).
Integrasi API WhatsApp Bot: Pengiriman pesan otomatis ke peserta atau guide (Masuk ke Future Development).
Deteksi Struk Palsu via AI/ML: Pengecekan keaslian bukti transfer menggunakan Machine Learning (Nice-to-have / Future Development).
Integrasi Payment Gateway Otomatis: Sistem mutasi otomatis via bank (Admin masih harus melakukan verifikasi/ double check foto struk di sistem).




5. Data Flow
Input Data: Peserta mendaftar dengan mengisi Google Form, lalu data tersebut otomatis terekam ke dalam Google Spreadsheet pelanggan.
Sinkronisasi Sistem: Admin login ke TripDash dan memasukkan tautan (URL) Google Spreadsheet tersebut ke dalam sistem.
Pemrosesan API: TripDash menarik data secara langsung melalui Google Sheets API.
Pengolahan Dashboard: TripDash merender data mentah tersebut menjadi tabel interaktif. Di tahap ini, admin dapat melakukan verifikasi pembayaran, mencetak PDF absensi, mengelola keuangan, dan mengelola inventaris barang.
6. Key Features & User Stories
6.1 Autentikasi & Keamanan
Story: Sebagai admin, saya harus bisa login ke dalam sistem dengan aman agar data pendaftaran dan keuangan pelanggan tidak bisa diakses oleh pihak luar.
6.2 Import & Data Mapping
Story: Sebagai admin, saya ingin memasukkan tautan Spreadsheet ke dalam aplikasi sehingga sistem dapat memetakan seluruh kolom data secara otomatis menjadi tabel yang rapi di dashboard.
6.3 Smart Payment Verification (Verifikasi Pembayaran)
Story: Sebagai admin, saya ingin sistem menghitung total tagihan peserta secara otomatis (berdasarkan pilihan Full Transport / Non-Transport dan tambahan fasilitas seperti Jas Hujan), sehingga saya tahu persis nominal yang harus dibayar peserta.
Story: Sebagai admin, saya ingin dapat memvalidasi status peserta menjadi "Lunas" atau "Belum Lunas", di mana sistem akan menampilkan nominal "Sisa Tagihan" untuk yang belum lunas, namun saya tetap memiliki akses untuk melakukan double check secara manual.
Story: Sebagai admin, saya ingin sistem mendeteksi kesamaan link/file bukti transfer antar peserta, sehingga saya bisa memverifikasi pembayaran peserta berombongan hanya dalam satu kali klik persetujuan.
6.4 Automated PDF Generator (Pencetak Absensi)
Story: Sebagai admin, saya ingin menyeleksi seluruh peserta (baik yang sudah lunas maupun belum) dan mencetaknya menjadi file PDF tabel absensi yang menyertakan informasi
No
Nama
Mepo

Story: Sebagai admin, saya ingin sistem mendeteksi nama gabungan di dalam satu baris sel data (contoh: "Budi + Andi") dan memecahnya secara otomatis menjadi dua baris/nomor urut absen yang berbeda di dalam file PDF akhir.
6.5 Flexible Finance Tracker (Pelacak Keuangan)
Story: Sebagai pengelola keuangan, saya ingin uang masuk (pemasukan) dicatat secara otomatis ke dalam buku kas berdasarkan tanggal dan waktu pengisian form (timestamp pendaftaran), sehingga riwayat arus kas menjadi akurat.
Story: Sebagai pengelola keuangan, saya ingin bisa menambahkan data pengeluaran secara kustom dan memfilter laporan akhir keuangan berdasarkan nama trip, minggu, bulan, atau tahun, sehingga saya bisa mengevaluasi keuntungan bisnis.
6.6 Inventory Management (Manajemen Barang/Inventaris)
Story: Sebagai admin, saya ingin melihat dan memperbarui stok ketersediaan barang operasional trip (misal: tenda, perlengkapan masak) dan barang sewaan (misal: jas hujan, headlamp), sehingga manajemen logistik tercatat dengan rapi.
